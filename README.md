# market-research-to-tiaozhanbei ｜ 市调转挑战杯大挑

为已有市场调研大赛作品的团队提供「挑战杯」大挑哲学社会科学类社会调查报告的迁移指导：审查旧作与资格，调整研究问题、章节和学术表达，整理图表，并核对最终文件。

从团队已有成果出发，按照**作品审阅 → 修改建议 → 已授权全文编辑 → 分项复核**推进。原始数据可选；没有底表也能审阅和编辑现有报告，但不能因此声称完成统计复现。默认中文，以 **2025年第十九届全国规则**为历史基准，目标届次和校内要求需另行核实。

> **当前版本：0.1.0-beta.1（测试版）。** 可用于指导、已有稿件编辑和人工辅助审核，尚未通过面向新手的稳定交付验收。上传和安装成功不等于生成的作品可直接参赛。已知限制见下文；真实研究及正式撰写由团队完成。

## 主要特性

- **先判断能否转，再判断如何转**：分别审查成果来源、原奖励、研究价值、证据范围与补充工作量，不把改标题当成完成转赛。
- **只有报告也能开始**：支持依据已有 PDF/Word 正文、图表、问卷和附录提出修改建议；原始数据不是接手门槛。
- **已有授权直接推进**：仅请求建议时，先给建议再询问是否生成修改版；已经明确要求修改版时，沿用授权，不重复等待代表小节或文风确认。
- **以研究问题组织章节**：把产品营销或商业方案中的可用调查证据，重新组织为有明确对象、问题与解释边界的社科论证，不补造新研究贡献。
- **保持原有研究展开程度**：以源作品建立摘要、正文和各章预算，核对文字、图表和分析内容；接受轻微篇幅差异，不设置统一页数，也不靠空白或套话补篇幅。
- **数据图与非数据图一起审查**：包括统计图、手绘图、政策图、照片及研究框架。先判断内容是否仍适用，再决定保留、局部修订或迁出，避免无必要的重绘。
- **正文与改稿说明分开**：论文独立成文；新旧对比、删改理由及核查任务集中记录。需要更新的研究框架默认预留作者补图位置，并给出提醒。
- **提供目录与具体复核提示**：要求交付时核对目录、图表、篇幅及引用，区分助手尚未完成的检查和团队需核实的事实。
- **支持项目续接**：在团队项目目录保存来源、版本、决策与审查记录，继续工作时沿用已确认的材料身份和偏好。

以上是工作流程与目标，不是对每次输出都能自动达标的保证。

## 工作标准与比赛要求

|事项|本 Skill 的约定|
|---|---|
|编辑范围|重排、润色与核对团队已有文本和证据；不凭空新增调查、访谈、采纳效果或核心研究结论|
|篇幅|完整编辑版参照源作品实质内容；用户要求限字提交版时另行处理，不自动压缩成长篇摘要|
|排版|默认图名表名居中，可编辑图表文字黑色，三线表顶底线1.5磅、表头分隔线0.5磅；原图文字与设计冲突时单独处理|
|参考案例|没有案例PDF时使用内置写作规律；用户可选补充案例，不以补充为开工条件|
|验收|结构、数值内容、图示、论证、引用、篇幅、版面和资格分别判断；机械检查不代替全文审查|
|正式申报|适用赛事通知优先；资格通过与编辑完成分别报告，不承诺可直接提交或获奖|

排版偏好、保留篇幅和作者补框架图是本 Skill 的默认工作约定，**不是全国赛事统一规定**。具体边界见[编辑与验收约定](references/execution-contract.md)。

## 阶段与交付

|当前任务|预期交付|
|---|---|
|判断旧作适用性|材料与资格状态、研究问题诊断、可迁移内容和证据缺口|
|确定迁移方向|候选题目、逐章迁移安排、研究与证据对应关系|
|提出具体修改意见|位置、问题、改法、理由及需要同步修改的内容|
|编辑已有全文|可编辑稿、保留或迁移的图表、目录；客观未决事项明确列出|
|审查最终文件|独立修改说明、全文审查记录、逐章篇幅对照、图表去向与复核提示|
|继续已有项目|读取版本和未完成项，推进可完成工作，避免重新询问已确认事项|

论文中保留必要、真实的研究局限；不能为了“独立成文”隐藏证据问题，也不能让正文变成编辑检查报告。

## 安装

仓库根目录就是技能目录。请保留整个目录结构，不能只复制 `SKILL.md`。

本仓库按私有仓库使用：安装者需要有仓库访问权限。命令行下载还需要 Git 及可用的 GitHub 身份验证；浏览器登录并不等于本地 Git 已登录。也可以使用下方 ZIP 方式。

### Windows（PowerShell）

```powershell
New-Item -ItemType Directory -Force -Path "$env:USERPROFILE\.agents\skills" | Out-Null
git clone https://github.com/YifeiWang2000/market-research-to-tiaozhanbei.git "$env:USERPROFILE\.agents\skills\market-research-to-tiaozhanbei"
```

### macOS / Linux

```bash
mkdir -p "$HOME/.agents/skills"
git clone https://github.com/YifeiWang2000/market-research-to-tiaozhanbei.git "$HOME/.agents/skills/market-research-to-tiaozhanbei"
```

这里采用 [Codex 官方说明](https://developers.openai.com/codex/skills/)中的用户级目录 `~/.agents/skills/`。已经在当前客户端识别的其他位置安装同名技能时，更新原副本即可，避免重复安装。

### 不使用命令行

1. 登录有访问权限的 GitHub 账号，在本仓库选择 **Code → Download ZIP**，或使用维护者提供的版本压缩包。
2. 解压，将包含 `SKILL.md` 的目录命名为 `market-research-to-tiaozhanbei`。
3. Windows 放入 `%USERPROFILE%\.agents\skills\`；macOS/Linux 放入 `~/.agents/skills/`。
4. 确认最终结构为 `skills/market-research-to-tiaozhanbei/SKILL.md`，不要多套一层文件夹。

### 确认安装与更新

在技能选择器中找到「市调转挑战杯大挑」，或发送：

```text
请使用 market-research-to-tiaozhanbei，先审阅我提供的市调报告。
```

技能未出现时重启客户端再检查安装位置。其他支持 Agent Skills 的工具，按该工具要求加载整个文件夹。

Git 安装后，进入技能目录执行 `git pull --ff-only` 更新；遇到本地改动先保留再处理，不强制覆盖。ZIP 安装则备份旧副本后替换。项目文件保持独立。

## 使用示例

### 先判断这份作品如何转赛

```text
请使用 market-research-to-tiaozhanbei 审阅附件。
这是本人/团队的市场调研大赛作品。
暂以2025年挑战杯大挑社科类要求为基准，原始数据暂不提供。
请先判断研究问题、证据与章节如何调整，给出具体修改建议。
参考案例使用内置写作规律，不额外添加。
```

建议阶段结束后，会询问是否依据建议生成编辑版；已有明确编辑授权时不重复询问。

### 已确定要编辑已有全文

```text
请使用 market-research-to-tiaozhanbei，直接编辑这份本人/团队已有报告。
保持源作品正文及各章的实质内容和图表展开，允许轻微篇幅差异。
依据现有证据调整表达，不添加不存在的调查或研究结论。
完成后提供带目录的Word文件，以及单独的修改说明、审查记录和复核清单。
```

### 自行补充参考案例

```text
请参考我另附的挑战杯案例，学习题目、摘要、章节论证和图表安排。
请区分案例与我方材料，不移用案例中的数据、访谈或结论。
```

### 续接与最终复核

```text
请读取当前项目中的 tiaozhanbei-transfer-project，继续处理未完成项。
核对最终文件的摘要、正文、图表和结论是否一致，并更新目录与交付状态。
```

提供目标届次正式通知后，可在项目中更新规则。只有明确需要限字提交版时，才按指定上限另行编辑，不用它替代完整版本。

## 工具与交付格式

- **已有报告**：PDF 或 Word；扫描PDF需要能查看页面或进行OCR的运行环境。
- **编辑成果**：优先可编辑 Word，按任务需要导出PDF并检查实际显示；修改说明和记录可以使用Markdown。
- **文献及规则核查**：需要联网访问可核验来源；未读到全文或无法确认的事项须如实记录。
- **机械检查脚本**：Python 3.9及以上，仅用标准库，不需安装第三方依赖。文档读取、编辑、渲染和OCR工具由运行环境提供，未打包进本仓库。

在技能目录运行测试：

```bash
python3 -I -S -m unittest discover -s tests -v
```

Windows 可将 `python3` 替换为已安装的 `py -3`。维护者或助手可使用下列命令辅助检查；普通用户无需手动运行：

```bash
python3 scripts/check_delivery.py --docx /path/to/report.docx --budget /path/to/acceptance-budget.json --output /path/to/check-result.json
```

预算需按真实源文件和最终文件填写，不能将空白模板当成已核验预算。可通过 `--table-reference` 指定经源页核对的表格内容基准。检查器成功运行或问题数为零，**都不等于论文通过验收**；输出中的待核事项与人工检查要求仍需处理。

## 版本状态与已知限制

**0.1.0-beta.1 是当前流程的封装版本，不是修复全部质量问题后的稳定版。**

截至2026年11月1日，44项机械检查脚本测试通过。最近一次真实作品编辑测试还发现：

- 研究目的和结果解释的证据强度可能未同步调整。
- 图内异常被发现后，可能仅加说明，尚未完成修订或退出论证的处理。
- 数据回查任务可能混入论文结论，影响独立成文。
- 分章预算虽有记录，内容承接仍需逐项核对。

此外，最终全页视觉复核、全部文献核验以及跨操作系统的完整编辑行为验证尚未全部完成。详细测试范围见[验证记录](references/validation.md)。本仓库不分发真实作品测试稿，也不以脚本测试替代研究质量验证。

反馈问题时，请说明版本、实际操作、预期结果和错误位置；尽量提供脱敏的最小示例，不上传受访者个人资料或无权分享的作品。

## 数据真实性与参赛边界

- 保留真实资料来源、调查时间与样本范围，不编造数据、访谈、专家意见、采纳证明、文献或政策。
- 无底表时可以编辑已有稿，但不能宣称完成统计复算；无法确认的冲突不凭猜测统一。
- 本人/团队作品并不自动满足目标比赛资格，原奖励、成果时间和作者贡献须核查。
- 2025规则基准涉及AI代替撰写调查报告的限制。此技能用于已有材料整理、修改反馈和自主写作支持，不把AI新增论证包装成学生已完成的原创研究。规则与来源见[2025规则基准](references/policy-2025.md)。
- 上传、联系组织方或代提交，需要相应任务授权；生成文件本身不包含提交授权。
